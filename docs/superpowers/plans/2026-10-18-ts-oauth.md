# Tailscale OAuth key minting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On every Start the web service mints a fresh, single-use, ephemeral, pre-approved, `tag:gpu` Tailscale auth key through the Tailscale API with an OAuth client, instead of reading a manually created key file (which expires or is spent).

**Architecture:** A small `TailscaleKeyMinter` in `apps/core` (client-credentials token, cached until near expiry, then `POST /api/v2/tailnet/-/keys`); `main.ts` chooses the `tsAuthKey` source: OAuth when `TS_OAUTH_CLIENT_ID` and `TS_OAUTH_CLIENT_SECRET` are both set, otherwise the existing key file (`TS_AUTHKEY_FILE`). No silent fallback when OAuth is configured.

**Tech Stack:** Node 20+, TypeScript strict, Vitest with a fake Tailscale API HTTP server.

**Spec:** `docs/superpowers/specs/2026-10-17-web-interface-design.md` (auth key section) and `docs/spikes/S5-authkey-and-vast-safety-net.md` (OAuth client with scope `auth_keys` and tag `tag:gpu`; the API's minimum `expirySeconds` is unmeasured).

## Global Constraints

- Everything in the earlier plans' Global Constraints applies (no hardcoded config: all values from `contracts/config-schema.yaml` component `apps`; env only in `apps/core/src/config.ts`; lint `python3 scripts/check_config_usage.py apps instance`; no secrets in logs/errors/responses/browser; English comments and commits; trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` for an opus implementer; never `--no-verify`; never `git add -f` anything under `.superpowers`).
- **Least privilege and fail closed:** the minted key is `reusable: false`, `ephemeral: true`, `preauthorized: true`, tags exactly `[TS_OAUTH_TAG]` (default `tag:gpu`), short expiry. If OAuth is configured and minting fails, Start fails with a typed reason and NO fallback to the key file.
- The OAuth client secret, the access token and the minted key never appear in logs, errors, API responses, the registry or the OpenAPI examples. Minted keys are added to the redaction set the lifecycle already uses for known secrets.
- Tailscale API base URL, token path, key path and TTL come from config (`TS_API_URL` default `https://api.tailscale.com`, `TS_KEY_TTL_S` default 3600, `TS_OAUTH_TAG` default `tag:gpu`); the path segments of the Tailscale API (`/api/v2/oauth/token`, `/api/v2/tailnet/-/keys`) are protocol constants (mark `config-lint: ok` only where the lint demands it).

### Task 1: Minter, config, wiring, docs

**Interfaces:**
- `createTailscaleKeyMinter(cfg: AppsConfig, deps?: {fetch?: typeof fetch, now?: () => number}): TailscaleKeyMinter | null` returns `null` when OAuth is not configured; `TailscaleKeyMinter.mint(): Promise<string>` throws `TailscaleError(code)` with `code` in `oauth_failed | key_rejected | tailscale_unavailable | invalid_response` (fixed strings; messages never include secrets, tokens, response bodies).
- Token: `POST {TS_API_URL}/api/v2/oauth/token` form body `grant_type=client_credentials`, `client_id`, `client_secret`; cache `access_token` until `expires_in` minus a safety margin; concurrent mints share one token request.
- Key: `POST {TS_API_URL}/api/v2/tailnet/-/keys` with `Authorization: Bearer <token>`, JSON `{capabilities:{devices:{create:{reusable:false, ephemeral:true, preauthorized:true, tags:[<TS_OAUTH_TAG>]}}}, expirySeconds:<TS_KEY_TTL_S>, description:"vast-comfy start"}`; response `{key: "tskey-auth-..."}` required to be a non-empty string; on HTTP 400 mentioning expiry retry ONCE with the documented larger value 86400 and record that fact in a fixed log line (`tailscale key ttl fallback`); HTTP 401/403 -> `oauth_failed` (and drop the cached token), 429/5xx/network -> `tailscale_unavailable`, other 4xx -> `key_rejected`.
- Use the shared capped/timed HTTP plumbing of apps/core (`http.ts`: size cap, timeout `HTTP_TIMEOUT_S_APPS`, `redirect: "error"`); the response size cap is `WEB_JSON_MAX_BYTES`.
- Lifecycle: add the start-failure reason `ts_key_mint_failed` (fixed identifier; mapped like `ts_key_missing`, response message in English, no provider text); the `tsAuthKey()` dependency may now throw `TailscaleError`.
- main.ts: if the minter is non-null use `() => minter.mint()` as `tsAuthKey` (and register each minted key for redaction), else the existing file reader; log one line at startup: `tailscale auth key source: oauth` or `file`. If exactly ONE of client id/secret is set: refuse to start the OAuth path and log a loud misconfiguration line (fail closed: Start returns `ts_key_missing`... choose `ts_key_mint_failed` with a clear startup warning).
- Docs: README section "Tailscale OAuth client" with the console steps (Settings -> OAuth clients -> Generate; scope Keys -> Auth Keys: Write only; tag `tag:gpu`; copy client id/secret into `.env` as `TS_OAUTH_CLIENT_ID` / `TS_OAUTH_CLIENT_SECRET`, never into chat), how to verify (Start works without any key file), and that revoking the client stops key minting. `.env.example` lists the two keys (empty) and the optional TS_* tunables commented.
